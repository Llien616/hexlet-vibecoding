# CLAUDE.md

## Контекст

«Метрика» — одностраничный русскоязычный калькулятор индекса массы тела и дневной нормы
калорий. Учебный эксперимент в репозитории `Llien616/hexlet-vibecoding`.

Задача страницы: по полу, возрасту, росту, весу, активности и цели сразу показать ИМТ,
дневную норму калорий, БЖУ и здоровый диапазон веса. Интерфейс обновляется на лету,
без кнопки «Рассчитать» и без отправки данных на сервер.

## Жёсткие ограничения

- Только чистые HTML, CSS и JavaScript. Нет сборки, npm-зависимостей, фреймворков и
  препроцессоров. Не добавлять их без явной просьбы.
- Все расчёты выполняются в браузере. Не добавлять аналитику, запросы к API, localStorage
  или отправку форм.
- Язык интерфейса — русский. Числа форматируются через `Intl.NumberFormat("ru-RU")`:
  десятичная запятая, неразрывный пробел в тысячах.
- Не менять формулы, границы категорий и коэффициенты без обновления README и проверки
  контрольных примеров из этого файла.

  1,55, цель «держу вес» → ИМТ 22,5, норма 2 172 ккал, здоровый вес 53,5–72,0 кг,
  БЖУ 163 / 72 / 217.
- Поля — `type="text"` с `inputmode`, а не `type="number"`: так принимается запятая.
  Парсинг — `Number(raw.replace(",", "."))`.

## Запуск и проверки

```bash
npx serve .                 # локальный сервер, обычно http://localhost:3000
node --check app.js         # синтаксис JS
```

Готового набора тестов и `package.json` нет. Для проверки в браузере можно использовать
Playwright ad hoc, не добавляя его в проект:

```bash
npx playwright screenshot --viewport-size="1440,1000" --full-page http://localhost:3000/
npx playwright screenshot --viewport-size="390,844" --full-page http://localhost:3000/
```

Обязательно проверять 1440, 1024, 900, 640, 390 и 320 px: горизонтального скролла быть не
должно. Также проверять клавиатурный фокус, очистку формы, невалидный ввод и консоль.

## Расчётная модель

- ИМТ: `weight / (height / 100) ** 2`.
- Категория определяется по ИМТ, округлённому до одного знака, — чтобы подпись совпадала
  с видимым числом. Маркер на шкале ставится по сырому ИМТ.
- Категории: `< 18,5` — дефицит массы; `< 25` — норма; `< 30` — избыточный вес;
  `< 35` — ожирение I ст.; `< 40` — ожирение II ст.; далее — ожирение III ст.
- BMR (Миффлин — Сан Жеор): `10 × вес + 6,25 × рост − 5 × возраст + 5` для мужчин,
  `− 161` для женщин.
- Активность: 1,2 · 1,375 · 1,55 · 1,725 · 1,9.
- TDEE: `BMR × коэффициент активности`.
- Цель: поддержание `×1`, похудение `×0,85` (дефицит 15%), набор `×1,1` (профицит 10%).
- Дневная норма: `Math.round(TDEE × коэффициент цели)`.
- БЖУ считается от округлённой нормы: белки `30% / 4`, жиры `30% / 9`, углеводы `40% / 4`,
  граммы округляются.
- Здоровый вес: `18,5 × рост²` — `24,9 × рост²`, один знак после запятой.
- «До нормы»: при ИМТ < 18,5 — `+` до нижней границы, при ИМТ ≥ 25 — `−` до верхней,
  иначе «уже в норме».
- Предупреждение: норма ниже 1 200 ккал для женщин и 1 500 ккал для мужчин.

Валидация: возраст 18–99, рост 120–230 см, вес 35–250 кг. Пустое поле не показывает
ошибку, но переводит результат в пустое состояние. Невалидное непустое поле получает
текст ошибки и `aria-invalid`.

Шкала ИМТ: диапазон 14–45, позиция в процентах с ограничением 0–100. Тики и подписи
строятся в `app.js`; лента целиком декоративная (`aria-hidden="true"`).

## UI и дизайн

- Палитра: фон `#E9E6EF`, поверхность `#FBFAFD`, чернила `#171320`, акцент
  `#FF5C2E`, тёмная панель результата `#171320`. Цвета зон: `#7B93FF`, `#3FC2AC`,
  `#F2B34C`, `#F0728F`.
- Шрифты: Bricolage Grotesque (заголовки и цифры), Golos Text (текст), IBM Plex Mono
  (подписи, единицы, служебные детали). Golos Text выбран из-за кириллицы — не заменять
  на латиноцентричный Instrument Sans.
- Сигнатурный элемент — измерительная лента ИМТ с оранжевым маркером. Не добавлять
  конкурирующие акценты; остальная часть страницы должна оставаться спокойной.
- Токены и компоненты — в `:root` и по классам в `styles.css`. Держать BEM-подобные
  имена (`block__element`, `block--modifier`), не плодить `!important`.
- Адаптив: 1020 px — одна колонка; 860 px — герой в столбец и методика в одну колонку;
  640 px — компактные отступы; 420 px — скрываются второстепенные детали.
- Доступность: видимый `:focus-visible`, подписи полей, `aria-describedby` для ошибок,
  скрытый live-регион с итогом, контраст мелкого текста не ниже 4,5:1,
  `prefers-reduced-motion` отключает анимации.
- Не использовать `alert()`, нативные `prompt()` и блокирующие диалоги.

## Стиль кода

- 2 пробела, двойные кавычки в JS, точки с запятой.
- `app.js` — один IIFE, константы в верхней части, функции чтения полей и отрисовки
  отдельно, без глобальных переменных.
- DOM обновляется через текстовые узлы и CSS-переменные, без `innerHTML` с данными
  пользователя.
- Не дублировать формулы в разметке: единственный источник истины — `app.js`.
- Комментарии — только там, где объясняют неочевидное; интерфейсные строки — по-русски.

## Git

- Основная ветка `main`, remote `origin` → `https://github.com/Llien616/hexlet-vibecoding`.
- Коммиты — короткие, в повелительном наклонении, на английском (как в истории проекта).
- Push выполняется через токен GitHub из окружения (`GITHUB_PERSONAL_ACCESS_TOKEN`).
  Никогда не записывать токен в файлы, URL или историю git.
- GitHub Pages включён: источник `main`, папка `/`, адрес
  `https://llien616.github.io/hexlet-vibecoding/`. В `index.html` закреплены `og:url`,
  `canonical` и абсолютный `og:image` на этот домен; при смене домена обновлять
  `og:url`, `og:image`, `twitter:image` и `canonical`.
- `Metrics-og.png` (1200×630) получена увеличением `Metrics.png` с полями под
  соотношение 1,91:1. При замене исходника пересобрать OG-версию, сохранив URL.

## Перед завершением задачи

1. `node --check app.js`.
2. Проверить контрольные примеры:
   - женщина, 30 лет, 170 см, 65 кг, 1,55, поддержание → 22,5 · 2 172 ккал;
   - мужчина, 30 лет, 180 см, 80 кг, 1,2, поддержание → 24,7 · 2 136 ккал;
   - женщина, 25 лет, 165 см, 40 кг, 1,2, похудение → 14,7 · 1 168 ккал и предупреждение.
3. Проверить пустое состояние, ошибку «От 35 до 250 кг» и кнопку «Очистить».
4. Проверить вёрстку на 1440 и 390 px, отсутствие горизонтального скролла и ошибок
   в консоли.
5. Если изменилось поведение или формулы — обновить README и этот файл.
6. Если менялись OG-теги или картинка — проверить живую страницу: теги в HTML,
   `og:image` отдаёт HTTP 200 и `image/png`.
